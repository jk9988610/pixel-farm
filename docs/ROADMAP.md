# 像素田园 · 未来规划路线图

> 版本：v1.0  
> 日期：2026-11-04  
> 基线：`main` @ `55b5835`（feat: Boss波次…）  
> 范围：仅覆盖仓库内 `demo/` 的可玩原型；`package.json` 为上游快照，不在路线图范围内  
> 编制方式：基于当前代码静态盘点，未做运行时性能实测

---

## 0. 核心结论

当前项目是一个**完成度较高的「幸存者-like 自动战斗」技术验证**，而不是一款农场游戏：种植、作物、土地、经济、存档均**未见实现**，玩家操控也**未见实现**（角色由内置 AI 自动移动、自动攻击）。

因此未来重心不建议继续堆叠 Boss/武器/敌人，而应：

1. **近期（1-2 周）完成「农场核心循环」垂直切片**：土地 → 播种 → 生长 → 收获 → 金币/经验，并补上真实输入与本地存档，让它先成为一款可玩的农场游戏。
2. **中期（3-6 周）把现有战斗系统改造成「夜间防卫」模式**，形成「白天种田、夜晚战斗、清晨结算」的双循环，让已有战斗代码转化为产品资产而不是沉没成本。
3. **远期（2-4 个月）做数据驱动与内容量产、架构拆分、移动端/PWA 平台化**，美术统一通过 Aseprite 管线产出。

优先级判断：**P0 = 农场循环、输入、存档、资产管线**；战斗扩展与音频/移动端为 P1；平台化与大规模内容为 P2。

## 2. 分阶段路线图

### 2.1 设计原则

- **垂直切片优先**：每个阶段结束都必须能部署、能玩、能验收，不做「只完成一半系统」。
- **数据驱动优先于硬编码**：作物、敌人、升级、价格应进数据表；当前角色属性/敌人/升级都写死在 JS 中。
- **保留战斗资产**：现有幸存者玩法不删除，改造为「夜间防卫」模式，复用敌潮、武器、升级、Boss。
- **像素规格先行**：新增内容必须符合第 4 节规范，避免后期返工。

### 2.5 暂缓 / 明确不做

- **暂缓**：继续新增 Boss、武器、敌人种类（在农场循环与双循环稳定前不再投入）。
- **暂缓**：多人联机、账号系统、云存档（当前无后端，成本与收益不匹配）。
- **不做**：为战斗系统引入 PixiJS/引擎重写（Canvas 2D 足够，重写属于纯成本）。
- **不做**：未经数据验证的平台迁移（小游戏/桌面封装）。

## 4. 美术与内容规划

### 4.1 工具链

- **唯一像素美术工具**：Aseprite `1.3.18.6-x64`，路径 `E:\tools\Aseprite-1.3.18.6-x64\aseprite.exe`。
- 现有素材由 Aseprite Lua 脚本程序化生成（`demo/_scripts/gen_*.lua`），通过 `Sprite/Image/drawPixel/saveCopyAs` 输出 PNG；脚本运行于 Aseprite 的 Lua 环境，不是独立命令行工具。
- 规划中的新增像素素材均要求：**Aseprite 源文件（`.aseprite`）+ 导出 PNG**，源文件建议放仓库 `art/`（不参与部署），导出目标放 `demo/assets/`。
- 建议逐步从「纯脚本生成」过渡到「`.aseprite` 手工精修 + 脚本批量导出」，脚本负责重复劳动，手工负责角色辨识度与动画节奏。

### 4.2 像素规格规范（建议）

| 类别 | 规格 | 帧/数量要求 | 锚点 |
| --- | --- | --- | --- |
| 角色 | 16×32 | 4 方向（down/up/side）；idle 2、walk 4、attack 4、hurt 1、die 4 | 底部中心 |
| 作物 | 16×16（小型）/ 32×32（大型） | 每作物 4 个生长阶段 + 1 个成熟态 | 底部中心 |
| 场景道具 | 树 32×48、灌木 24×16、石头 16×12、花圃 32×20 | 每种 2-3 个变体 | 底部中心 |
| 地块 | 32×32 | 草地/泥土/湿土/已耕地等，至少 8 种 | 左上角对齐网格 |
| 建筑 | 48×48 / 64×64 | 鸡舍、谷仓、商店各 1-2 级 | 底部中心 |
| UI | 9-slice 面板 + 16×16 图标 | 金币、种子、工具、作物、心、时钟等 | 左上角 |
| 特效 | 16×16 / 32×32 序列帧 | 收获、浇水、升级、升级卡边框 | 中心 |

调色板建议固定一套 24-32 色主色板（当前脚本内颜色分散定义），新增素材从同一色板取色，保证整体统一。

### 4.4 资产工作流（建议落地）

1. 在 Aseprite 中建立 `.aseprite` 源文件，按「角色 / 作物 / 地块 / 建筑 / UI」分目录。
2. 使用 Aseprite CLI 批量导出帧序列或图集，例如：

   ```powershell
   & "E:\tools\Aseprite-1.3.18.6-x64\aseprite.exe" -b art\crops\carrot.aseprite --sheet demo\assets\sv\crops\carrot.png --data demo\assets\sv\crops\carrot.json
   ```

3. 由 manifest 生成脚本扫描导出目录，写入 `demo/assets/char/manifest.json` / `demo/assets/sv/manifest.json`。
4. 提交前校验：帧尺寸一致、透明背景、锚点一致、文件名 `frame_N.png` 连续。
5. 部署时排除 `.aseprite` 源文件与 `_scripts/`。
