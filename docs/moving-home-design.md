## 1. 现状（读代码确认）

### 1.1 世界与坐标

- 逻辑视口 `LOGIC_W=640 / LOGIC_H=360`，世界 `WORLD_W=1600 / WORLD_H=1200`（play.html 253-254）。
- 相机 `camX/camY` 跟随受控角色 `activeChar`，并 clamp 在世界内（reset 1968-1972）。
- 所有 Actor（玩家、伙伴）、敌人、子弹、掉落物都存**绝对世界坐标** `x/y`。

### 1.2 农场的存储方式

农场不是独立对象，而是一组模块级常量 + 一个 9 元素数组：

| 常量/数据 | 值 | 说明 |
|---|---|---|
| `FARM_COLS / FARM_ROWS` | 3 / 3 | 地块网格 |
| `FARM_CELL` | 34 | 单块边长 |
| `FARM_GAP` | 2 | 块间距 |
| `FARM_W / FARM_H` | 106 / 106 | `3*34 + 2*2` |
| `FARM_X0` | 747 | `round(1600/2 - 106/2)`，**绝对世界坐标** |
| `FARM_Y0` | 652 | `1200/2 + 52`，**绝对世界坐标** |
| `HOME_X / HOME_Y` | 800 / 705 | 由 `FARM_X0/Y0 + FARM_W/H/2` 派生，**绝对世界坐标** |
| `plots[0..8]` | `{state,crop,start}` | 无坐标字段，位置由索引派生 |

- `plotPos(i)`（957-960）：`col = i % 3, row = i / 3`，返回
  `[FARM_X0 + col*(FARM_CELL+FARM_GAP), FARM_Y0 + row*(FARM_CELL+FARM_GAP)]`，步长 36。
- 全部农事（`nearestPlot` 962-972、`farmAction` 984-1022、`drawFarm` 1203-1246）都只通过 `plotPos(i)` 取位置。
- 关键结论：**地块数据本身已经是“家园相对”的**（索引即行列），绝对量只剩原点 `FARM_X0/FARM_Y0` 两个常量，以及由它们派生的 `HOME_X/HOME_Y`。
- 现状的“家园”只有 3x3 耕地 + 派生中心点：没有独立建筑/精灵、没有碰撞体、没有名字或 UI 入口。

### 1.3 作物状态与生长计时

- `plots` 元素为 `{state:'empty'|'growing'|'ready', crop:0..4, start:秒}`（777-780）。
- `updateFarm(dt)`（974-982）：`farmTime += dt`；`farmTime - p.start >= CROPS[p.crop].grow` 时置 `ready`。
- 播种时 `p.start = farmTime`（1017）；`drawFarm` 用 `(farmTime - p.start)/grow` 算生长阶段（1217-1218）。
- 关键结论：**生长只与时间轴 `farmTime` 和 `start` 有关，与坐标完全解耦**。移动家园不需要、也不能改写 `start`。

### 1.4 每日行情

- `sellPrice(i, day=dayNumber)`（759-761）：`1 + 0.10*sin(day*1.3 + i*1.9)` 的确定性浮动；`priceTrend` 对比 `dayNumber-1`。
- 行情不落盘，刷新后由 `dayNumber` 重算；与家园位置无关。

### 1.5 存档字段（v2）

`SAVE_KEY = 'pixel-farm-save-v1'`（键名不随版本变），`SAVE_VERSION = 2`（1033-1034）。payload 字段（1058-1081）：

`version, savedAt, coins, level, xp, xpNext, selectedCrop, farmTime, phase, phaseT, nightKills, dayNumber, seeds[], produce[], plots[{state,crop,start}], stats, chars{player:{char,stats}, partner:{char,stats}}, activeRole`

- **不存家园位置**，也不存任何世界坐标；地块坐标全靠常量派生。
- `loadGame`（1089-1147）：只接受 `version === 1 || 2`；强制校验 6 个数值字段与 `plots` 数组长度恰好 9；`phase/phaseT/nightKills/dayNumber/seeds/produce/chars/activeRole` 均为“后加可选字段，缺省不判损坏”。
- v1 只有 `stats`，视为玩家属性，伙伴按默认生成（1107-1113）。

### 1.6 已经使用「家园坐标」的地方（接缝清单）

| 位置 | 行号 | 用法 |
|---|---|---|
| `plotPos` | 959 | 地块世界坐标 |
| 守卫接战判定 | 1398 | 圈外敌人不打 |
| `guardDir` 找敌 | 1466 | `nearestEnemyTo(HOME_X, HOME_Y, GUARD_R)` |
| `guardDir` 拉回 | 1469 | 距家园超过 `GUARD_R+20` 就回中心 |
| `guardDir` 巡逻 | 1477-1478 | 中心附近 38x26 小圈 |
| 守卫圈渲染 | 2476 | 以 `HOME_X/Y` 画虚线圆 |

`FARM_W/FARM_H` 只在派生 `HOME_X/HOME_Y` 处使用。除此之外无任何地方直接依赖农场绝对坐标。

### 1.7 其他相关事实

- 玩家出生点由 `Actor` 构造固定为 `(WORLD_W/2, WORLD_H/2) = (800,600)`（1319-1320），`reset` 不再改玩家位置；伙伴出生在玩家 `+36/+10`（1919-1920）。注意出生点 y=600 与家园中心 y=705 并不重合。
- 敌人生成以受控角色为中心、半径 360-440（1567-1586）**与家园无关**。
- 当前没有地图/小地图实现（全文件无 minimap 相关代码）。

## 2. 目标形态

### 2.1 家园 = 实体 + 相对格子偏移

引入唯一的可变家园状态，表示**家园左上角（0 号地块左上角）的世界坐标**：

```
home = { x: 747, y: 652 }        // 初值等于现有 FARM_X0/FARM_Y0
```

选择“左上角原点”而不是“中心点”的理由：

1. `plotPos` 天然以左上角为基准，改造成本最低（把常量换成 `home.x/home.y` 即可）；
2. 中心点是既有派生量，改成由 `home` 派生，可保证守卫圈与耕地严格同心；
3. 存档只存一个原点，不存在“中心 + 内部偏移”两套基准互相换算的漂移风险。

派生规则（替代现有常量）：

- `homeLeft/top = home.x/home.y`
- `homeCenterX = home.x + FARM_W/2`、`homeCenterY = home.y + FARM_H/2`（替换 `HOME_X/HOME_Y`）
- `plotPos(i) = [home.x + col*(FARM_CELL+FARM_GAP), home.y + row*(FARM_CELL+FARM_GAP)]`

尺寸常量（`FARM_COLS/ROWS/CELL/GAP/W/H`）保持不变；地块仍以索引 0..8 表达相对位置，**不在地块里存坐标**。

建议落地形态：把 `HOME_X/HOME_Y` 从常量改为函数/读取函数（如 `homeCenter()`），并在代码里一次性清除对 `HOME_X/HOME_Y` 常量的直接引用，避免守卫逻辑与渲染读到不同步的旧值。这是本设计里最容易漏改的点。

### 2.2 移动时的视觉处理

- `drawFarm` 每帧用 `plotPos(i)` 求屏幕坐标，因此只要 `home` 变了，**9 块地和已种下的作物会在下一帧整体平移**，无需改绘制分支。
- 视觉表现建议按搬迁方式区分：
  - 定居点式搬迁：允许一次 0.2-0.4s 的整体位移补间，或一次短暂淡出/淡入；补间只影响绘制偏移，不改 `home` 的逻辑值（逻辑值在确认瞬间就更新）。
  - 若不做补间，直接瞬移也可用（当前渲染没有依赖旧坐标的缓存）。
- 不做“每块地独立动画”，避免 9 块地不同步造成的数据/视觉不一致。

### 2.3 移动时的逻辑处理

- `nearestPlot()` 与 `farmAction()` 走 `plotPos`，家园移动后交互点自动跟随；玩家离得远就是“靠近地块再按空格”，行为自然。
- 生长计时：`farmTime` 继续累加，`p.start` 原样保留 → **移动期间正在生长的作物剩余时间不变**，成熟时刻与移动无关。
- 移动不重置 `farmTime`、不清空 `plots`、不改变 `state/crop`。
- 边界约束：`home.x ∈ [0, WORLD_W-FARM_W] = [0,1494]`，`home.y ∈ [0, WORLD_H-FARM_H] = [0,1094]`，保证 9 块地完整落在世界内（现有 747/652 在范围内）。
- 移动过程中的农事是否锁定输入：**待确认**（建议不锁定，按新坐标即时判定，逻辑更简单）。
- 家园是否阻挡角色移动：现状地块无碰撞，本设计维持“可穿过”。

## 3. 迁移路径（v2 → v3）

### 3.1 数据结构改动

| 对象 | 现状 | 改为 |
|---|---|---|
| 家园原点 | 常量 `FARM_X0/FARM_Y0` | 可变 `home = {x, y}`；常量降级为 `DEFAULT_HOME` |
| 家园中心 | 常量 `HOME_X/HOME_Y` | 由 `home` 派生的读函数（守卫/渲染共用） |
| `plotPos(i)` | 常量 + 行列 | `home` + 行列，公式不变 |
| `plots[i]` | `{state,crop,start}` | 不变（仍不存坐标） |
| 存档 | v2，无位置 | v3，新增 `home:{x,y}` |

### 3.2 存档 schema（v3）

```
version: 3,
home: { x: <number>, y: <number> },
... 其余字段与 v2 完全一致
```

- `SAVE_KEY` 保持 `'pixel-farm-save-v1'`（与既有 v1/v2 共用同一键，不迁移旧键）。
- `SAVE_VERSION = 3`；`saveGame` 只增加一个 `home` 字段，`plots` 序列化格式不变。
- 体积与写入频率无实质变化。

### 3.3 旧档兼容与回填

沿用现有“后加可选字段缺省不判损坏”的原则（与 `phase/seeds/produce` 一致）：

1. `loadGame` 版本判断放宽为 `1 | 2 | 3`；
2. v3：读 `home`，要求 `x/y` 为有限数值，并 clamp 到 §2.3 的世界边界；不合法则回填默认并继续读档，**不判损坏**；
3. v1/v2：无 `home`，直接回填 `DEFAULT_HOME = {x:747, y:652}`；因为该默认值与旧代码的 `FARM_X0/FARM_Y0` 逐像素一致，9 块地、作物、守卫圈位置全部保持不变，等于零迁移成本；
4. `plots` 的索引语义不变，不做任何坐标回填；
5. `saveGame` 下一次写盘即升级为 v3。

### 3.4 回滚与风险说明

- 旧客户端（v1/v2 代码）遇到 `version === 3` 会 `return false` → 当作新档启动，并在随后自动存档时覆盖进度。**发布说明中需注明该版本不可回滚**。
- 备选方案：保持 `version === 2` 并把 `home` 当可选字段写入（旧客户端不会判损坏，只会忽略），代价是版本语义模糊。**待确认**是否采用。
- 若产品要求“搬迁失败/取消绝不改存档”，需保证确认写入前的所有路径都不触发 `saveGame`。

## 4. 家园怎么移动

| 方案 | 一句话取舍 |
|---|---|
| A. 玩家主动控制家园移动 | 可控性最好、最像“可移动实体”，但要新增拖拽/放置输入模式与 UI，且移动中玩家容易离开农田，操作负担最大。 |
| B. 家园持续跟随玩家 | 实现最省事（每帧同步 `home`），但家园与守卫中心一直在漂移，地块交互点抖动，直接破坏“家园=据点”的节奏，也和守卫/敌人生成逻辑冲突。 |
| C. 定居点式（到地区确认搬迁） | 只有确认瞬间写一次位置，与现有守卫圈、昼夜节奏、确定性世界最契合，UI 成本低；代价是搬迁有仪式感但不够“自由移动”。 |

**推荐 C：定居点式 + 人工确认**（到达指定地区后弹出“在此安家”确认，确认后整块家园与全部地块一次性搬迁）。

理由：本作的守卫任务、敌人生成、昼夜节奏都建立在“玩家在世界里跑、家园是固定据点”的结构上；C 只改一次位置写入，不引入每帧同步、不新增输入模式，迁移风险最小。A/B 可作为后续玩法扩展，不属于本版。

## 5. 与其他系统的接缝

1. **守卫任务（必须同步改）**：`guardDir`（1466/1469/1477-1478）、自动攻击过滤（1398）、守卫圈渲染（2476）共 6 处引用 `HOME_X/HOME_Y`，全部改为派生的 `homeCenter()`。搬迁后伙伴是否立刻按新中心巡逻、还是让守卫伙伴先走回新家园：**待确认**（建议不传送，让它自行走回，避免瞬移穿模）。
2. **存档**：新增 `home` 字段与 v3，见 §3；出生点、相机、任务状态均不进存档，无需改动。
3. **地图/小地图（未来）**：当前无实现（**待确认**未来是否做）。若做，家园作为 POI 用 `homeCenter()` 即可，存档已有 `home`；地图缩放/裁剪不能缓存旧坐标。
4. **多人伙伴**：当前仅 1 个伙伴，`patrolSeed` 已支持多伙伴巡逻相位错开；多伙伴守卫只要统一读 `homeCenter()` 即自动跟随新家园。若未来“每个伙伴一个家园”，需要 `homeId` 维度，本版明确不做。
5. **玩家出生点/相机**：`Actor` 出生点固定 (800,600)，`reset` 不随 `home` 变。是否改为“出生在家园旁”：**待确认**（会改变现有开局体验，本版建议不动）。
6. **敌人生成**：以受控角色为中心生成（1567-1586），与家园无关；定居点式搬迁不会改变生成规则，但玩家远离家园期间守卫伙伴可能一直空转——属预期行为，**待确认**是否需要“远离家园时自动暂停守卫”。
7. **HUD**：现有 HUD 不展示家园位置/区域名；若要提示“已在新家园”，属阶段 3 的表现项。

## 6. 明确的非目标（本版不做）

- 不做家园实时跟随玩家、不做拖拽式自由摆放（方案 A/B 不落地）。
- 不做多家园、多据点、家园建造/扩建、田地扩容或田块增删。
- 不做地图/小地图 UI（若未来做，只保留 POI 接缝）。
- 不改作物经济：不改 `CROPS` 成本/售价/生长时间，不改行情公式，不改 `farmTime` 语义。
- 不做家园/地块碰撞与地形改动，角色仍可穿过地块。
- 不改伙伴数量（仍为 1），不做“一个伙伴一个家园”。
- 不新增美术资源与音效；搬迁最多做一次简单位移/淡入淡出。
- 不做旧客户端对 v3 存档的兼容（接受不可回滚）。
- 不做旧档坐标重算/历史位置回溯（旧档统一回填默认家园）。

## 7. 分阶段实施建议

### 阶段 1：数据与存档（无玩法变化，可独立上线）

- 引入 `home = {x,y}` 与 `DEFAULT_HOME`；`plotPos` 与守卫 6 处引用改为 `home` 派生；存档升 v3，`loadGame` 接受 v1/v2/v3 并回填。
- 验收点：
  1. 新档、v1 档、v2 档都能正常进入，进度与库存不变；
  2. 9 块地、作物生长阶段、守卫圈中心与改动前完全一致（位置与现状逐像素相同）；
  3. 刷新后家园位置保持；
  4. 搬迁（此时可先用调试写入）后刷新，位置与作物剩余时间都不变；
  5. `home` 缺失/NaN/越界时回填默认且不判存档损坏。

### 阶段 2：定居点式搬迁（最小玩法）

- 世界内放置 2-3 个安家点（数量与位置**待确认**），到达后触发确认；确认时写入 `home` + clamp + `saveGame`；守卫伙伴改以新中心巡逻。
- 验收点：
  1. 确认后 9 块地、正在生长的作物、守卫圈同步到新位置；
  2. 生长中的作物剩余时间与搬迁前一致（`start` 未被改写）；
  3. 搬迁后刷新恢复新位置；
  4. 取消/条件不足时不触发任何存档写入；
  5. 旧档（v1/v2）也能搬迁并升级为 v3。

### 阶段 3：表现与可用性（可选）

- 搬迁过渡（0.2-0.4s 位移或淡入淡出）、HUD/飘字提示；若已有地图则加家园 POI。
- 验收点：
  1. 过渡期间无坐标错位，结束帧与 `home` 逻辑值一致；
  2. 过渡不阻塞农事与战斗（或明确锁定并给出提示，二选一）；
  3. 过渡中断（切后台/死亡重置）后位置仍与存档一致。
