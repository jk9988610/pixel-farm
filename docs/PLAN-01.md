# 第 1 批次工作计划（PLAN-01）

> 批次目标：把 ROADMAP 近期 P0（N1-N4）落成可验收的「农场垂直切片」  
> 基线：`main` @ `e268b94`（docs: 新增未来规划路线图）  
> 计划日期：2026-11-04  
> 执行顺序：B1 → B2 → B3 → B4，每项独立提交；全部自验通过后统一部署

---

## 1. 批次范围与验收总目标

本批次完成后应达到：

1. 资产脚本不再指向旧仓库路径，`assets/sv/manifest.json` 登记全部 12 张图，画廊完整。
2. 玩家可用键盘/方向键移动、触屏拖动移动，`Esc` 暂停/继续；不再默认由 AI 代打移动。
3. 世界内存在 3×3 地块与 3 种作物，可完成「买种→播种→生长→收获→金币/经验」闭环。
4. 关闭/刷新页面后，金币、等级/经验、作物进度与地块状态通过 `localStorage` 恢复。
5. 战斗仍可运行：敌人、自动攻击、升级、Boss 逻辑不被破坏；页面无控制台报错。
6. 本批次结束时执行部署；部署前做远程目录备份，部署后校验 `play.html` 与关键资源。

## 4. 提交与验证策略

1. 先单独提交本计划：`docs: 新增第 1 批次计划`。
2. 每个条目完成后单独提交，提交信息中文说明「做了什么 + 为什么」，例如：
   - `fix: 修复资产生成脚本路径并重生成场景素材索引`
   - `feat: 加入键盘/触屏移动与暂停`
   - `feat: 加入3x3地块与三种作物种植收获`
   - `feat: 加入localStorage存档v1`
3. 提交只按文件名 `git add <file>`，禁止 `git add -A`，确保 `demo/assets/char/README.txt` 不被带入。
4. 全部完成后本地起静态服务自验：页面可加载、无控制台错误、可移动/暂停/种植/收获、刷新可恢复、战斗仍运行。
5. 部署前备份：

   ```bash
   ssh aliyun-ab "cd /var/www && tar czf /tmp/play.bykc.click-backup-$(date +%Y%m%d%H%M).tgz play.bykc.click"
   ```

6. 执行 `deploy.cmd`，确认脚本 200 探测通过，并额外抽查 `https://play.bykc.click/assets/sv/manifest.json` 等关键资源。

- 资产重生成若缺源文件：保留现有 PNG，仅修脚本与 manifest，并在结论中说明「未重跑 PNG 生成」。
